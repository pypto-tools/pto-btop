# pto-btop v0.4.0-alpha.1

Initial preview of terminal monitoring for up to four Linux machines. Agents
upload over HTTPS to a central hub; viewers can run on every monitored machine.

- btop-derived CPU, memory, disks, network and process panels with differential
  terminal rendering, per-viewer process filtering and host selection.
- Certificate/name verification, separate agent/viewer credentials, host access
  control, stale/offline reporting and reconnect after a hub restart.
- Linux amd64/arm64 packages with all three commands, themes, configuration
  generator, licenses, runtime preflight and installation/upgrade tooling.
- `pto-btop`, `pto-btop-agent`, `pto-btop-server` command entries; original internal
  executable names are retained. No automatic service activation.

Requirements: glibc Linux, OpenSSL 3 shared libraries, Python 3.10+ for tooling,
and the OpenSSL CLI when generating configuration. Inspect `package.json` or run
`python3 install.py --check` for the asset's exact glibc requirement.

The release workflow requires both architecture jobs to pass before attaching
assets to a draft. Tests include real local HTTPS agents, independent terminal
sessions, certificate and access checks, restart recovery and installation
upgrade/rejection behavior. They do not constitute a three-physical-machine
deployment test. Actual machine deployment and extended load/overhead validation
remain pending. History is in memory; certificate renewal is manual. There is no
GPU/NPU collection, HA or persistent historical database in this preview.

Verify the `.sha256` file, extract the matching archive and read its README.
Installation preserves configuration and state. Explicitly restart existing
services after upgrading. The initial release has no prior package migration.
