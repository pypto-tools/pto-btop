# pto-btop v0.6.0

新增按用户、服务器和集群查看的卡时统计，提供 Linux amd64 / arm64 正式安装包。

## 卡时统计

- 总览增加每台服务器的 CARD-H 摘要；三台布局的集群面板显示已知卡时总数和数据覆盖率。
- 按 `h` 打开卡时页，`p` 切换今日 / 7 天 / 30 天，`Tab` 切换当前服务器 / 所有服务器。今日显示服务器用量对比，7/30 天显示每日用量图。
- `/` 按用户名子串筛选，忽略大小写；上下键选择，PgUp/PgDn 翻页，Home/End 到首尾。筛选只影响用户表，同名账号不会跨服务器自动合并。
- 详情按大写 `H` 在 CARDS 区切换设备 / USAGE。保留 CPU、MEM、DISKS、NET、PROC 及原有卡列表翻页，继续使用当前主题和帧差分刷新。
- 卡时表示占用卡数乘以时间，不是硬件利用率。历史不完整标记 `*`，未知显示 `--`，失联或过期旧值标记 `old` 并停止增长；仅在起点已知时显示历史覆盖日期。
- 自然日默认使用 UTC；只有时区与窗口起点一致的节点才参与合并，不匹配或缺失的数据会标明。

agent 独立每 30 秒查询一次卡时接口，硬超时 1 秒，120 秒后标记过期；不随界面刷新重复查询。
新增指标组通过能力协商启用，旧 agent 仍可提供原有指标。包内包含卡时指南、接口说明、示例和模拟预览图。

## 数据源要求

每个节点需要支持 `task-submit --usage-monitor --json` 的 task-submit，并正常运行卡时 publisher。
普通 agent 无需 sudo。task-submit 独立维护增量账本和每日汇总，pto-btop 读取只读快照。

本包不包含 task-submit。Python 3.9 节点还需要 task-submit 的兼容性修复
（[npu-taskqueue #23](https://github.com/pypto-tools/npu-taskqueue/pull/23)）；
如果 publisher 因 `Path.stat(follow_symlinks=False)` 报错而没有快照，仅升级 pto-btop 不会恢复卡时数据。

## 升级与预览

先升级中心，再升级各节点的 task-submit / agent 和查看端。共享服务安装的机器分别执行：

```bash
sudo pto-btop-update
# 访问 GitHub 需要代理时：
sudo pto-btop-update --proxy http://127.0.0.1:7892
```

既有配置、证书和状态继续保留，无需重新分发配置。系统更新命令按本机角色重启服务；
查看端需退出并重新打开 `pto-btop`。用户目录安装可下载本次 Release 的 `setup.py` 和校验文件，在原配置目录运行。

不连接真实服务器也可以查看模拟界面：

```bash
pto-btop --demo --demo-hosts 3 --usage
```

Linux 运行要求仍为 glibc 2.28+，包内静态链接 OpenSSL 3.5.9 和 GCC C++ runtime。

## 验证

发布流程在原生 amd64 / arm64 的 glibc 2.28 环境构建并运行采集、协议、HTTPS、终端、打包及安装升级测试。
卡时回归覆盖筛选、翻页、缩放、部分历史、未知覆盖日期、过期数据及帧差分一致性；
打包回归检查新增离线文档和校验清单，以及升级后配置和状态保留。
