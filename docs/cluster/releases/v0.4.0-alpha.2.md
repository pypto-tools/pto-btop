# pto-btop v0.4.0-alpha.2

Fix installation on Linux hosts with older system libraries, including ARM64
machines with glibc 2.34 and OpenSSL 1.1.1.

- Build amd64 and arm64 packages with a glibc 2.28 baseline.
- Bundle OpenSSL 3.5.9 and the GCC C++ runtime; system OpenSSL 3 is no longer required.
- Add a downloadable `setup.py` enrollment installer with pinned package checksums,
  HTTP/SOCKS proxy support and explicit check-only/install-only modes.
- Generate certificates with an explicit OpenSSL configuration to avoid duplicate
  extensions on OpenSSL 1.1.1 distributions. Existing certificates are preserved.
- Keep existing node configuration and credentials when installing a new version.

Python 3.10+ is still required for installation; `uv run --no-project --python 3.12`
can provide it without upgrading the system Python. uv does not change system glibc.

If you already have a private enrollment bundle, download `setup.py` and
`setup.py.sha256` into that directory, verify the checksum and run
`uv run --no-project --python 3.12 setup.py`. Add `--proxy URL` when needed and
set `HTTPS_PROXY=URL` for uv's Python download. `--check` does not install anything.
See [the installation guide](https://github.com/pypto-tools/pto-btop/blob/v0.4.0-alpha.2/docs/cluster/release.md).

CI covers both native architectures, real HTTPS traffic, terminal sessions,
package installation, upgrades, preserved enrollment and failed installations.
Existing hub and agent configurations remain compatible. Restart running services
explicitly after upgrading. This remains a prerelease; remote host acceptance
must be confirmed on the actual machines.
